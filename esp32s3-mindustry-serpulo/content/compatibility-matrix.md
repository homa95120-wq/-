# Матрица совместимости — Серпуло на ESP32-S3 N16R8

База: Mindustry v160.7 (коммит 17012d61). Три измерения разделяются строго:
1. **Полнота контента** — есть ли все блоки, предметы, юниты, сектора.
2. **Совместимость механик** — насколько поведение совпадает с оригиналом.
3. **Масштаб симуляции** — сколько объектов одновременно выдерживает ESP32.

## 3. Масштаб симуляции (ESP32-S3 N16R8)

| Параметр | Оригинал (ПК) | Порт (предварительно, без замеров) |
|---|---|---|
| Активных секторов одновременно | все планетные секторы по очереди с фоновым обновлением | **1 активный сектор** |
| Фоновый расчёт остальных секторов | полная симуляция | упрощённая модель (производство/потребление/волны) |
| Зданий на активном секторе | сотни | лимит TBD (измерение на плате) |
| Юнитов одновременно | десятки–сотни | лимит TBD |
| Пуль/снарядов одновременно | сотни | лимит TBD |
| Частота кадров | 60 FPS | цель 30 FPS |
| Графика | полные спрайты, частицы, освещение | упрощённые спрайты, уменьшенные частицы |

**Ключевое отличие от оригинала:** в оригинале движок может держать состояние всей кампании с периодическим фоновым обновлением секторов; на ESP32 из-за 512 КБ SRAM активна только одна карта сектора, остальные считаются по статистической модели. Сохранение всего контента при этом не страдает — страдает только одновременный масштаб.

## 4. Что нельзя сохранить без отдельного решения

- Оригинальные файлы сохранений Mindustry (формат и версия не совместимы).
- Моды Mindustry (загрузка JSON/Java-классов оригинала).
- Сетевой мультиплеер (протокол, серверы).
- Бит-в-бит идентичность траекторий пуль, экономики и баланса.

Любое из вышеперечисленного требует отдельного исследования и явного согласования перед реализацией.

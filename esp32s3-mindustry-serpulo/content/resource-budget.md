# Ресурсный бюджет — ESP32-S3 N16R8 (предварительный расчёт)

Аппаратное железо: ESP32-S3 N16R8 — 2 ядра × до 240 МГц, 512 КБ внутренней SRAM, 8 МБ PSRAM, 16 МБ flash.

> **Важно:** в текущем окружении нет ESP-IDF инструментария и реальной платы. Все цифры — **предварительные расчёты**, подлежащие подтверждению на этапе 5 (замеры на плате). Без платы нельзть претендовать на точность.

---

## 1. Распределение памяти по типам данных

| Тип данных | Размещение | Объём (оценка) | Комментарий |
|---|---|---|---|
| Код прошивки + ESP-IDF | flash | ~1–2 МБ | включая библиотеки, драйвер дисплея, файловая система |
| Статические ресурсы контента (предметы, жидкости, блоки, юниты, сектора, рецепты, техдерево, волны) | flash (сжато) | ~0.5–1.5 МБ | 138 блоков, 35 юнитов, 22 предмета, 11 жидкостей, 272 сектора — компактные таблицы |
| Атласы спрайтов и текстуры блоков/юнитов | PSRAM | ~2–4 МБ | упрощённая графика, уменьшенные спрайты по сравнению с оригиналом |
| Карты активных секторов (тайлы + постройки) | PSRAM | ~1–2 МБ | один активный сектор в памяти, остальные на microSD/flash |
| Горячие данные симуляции (тайлы, здания, юниты, пули, электросеть, очереди) | внутренняя SRAM | ~128–256 КБ | критично для latency; не превышать 512 КБ |
| Сохранения campaña (прогресс секторов, исследования) | flash / PSRAM (или microSD) | ~64–256 КБ | без microSD — ограничен объёмом flash-раздела |
| Аудио (музыка, звуки) | microSD (опц.) или flash | — | микроSD не считается установленной; без неё аудио урезано/отсутствует |
| Стек задач, буферы дисплея, сеть | SRAM | ~64–128 КБ | зависит от разрешения экрана и интерфейса |

**Итого SRAM (горячее):** ориентировочно 256–400 КБ из 512 КБ — вписывается, но с небольшим запасом. Перерасход требует переноса структур в PSRAM или減шения лимита объектов.

## 2. Разметка разделов flash (предложение)

| Раздел | Размер | Содержимое |
|---|---|---|
| NVS | 16–32 КБ | настройки, калибровка |
| OTA data | 8–16 КБ | метаданные обновлений |
| OTA app 0 | ~2 МБ | основная прошивка |
| OTA app 1 | ~2 МБ | резервная прошивка |
| SPIFFS/LittleFS | ~4–8 МБ | ресурсы контента, спрайты, сохранения, карты |
| Прошивка загрузчика | 32 КБ | bootloader |

Итого: укладывается в 16 МБ flash с запасом.

## 3. Бюджет времени кадра (цель 30 FPS ≈ 33 мс)

| Компонент | Лимит (оценка) | Комментарий |
|---|---|---|
| Обновление симуляции сектора (здания, юниты, пули, конвейеры, жидкости, электричество) | 10–15 мс | зависит от лимита объектов |
| Поиск пути и принятие решений юнитами | 3–5 мс | иерархический поиск, реже пересчёт |
| Рендер (дисплей через SPI/I8080/RGB) | 5–10 мс | зависит от разрешения и 인터фейса |
| Фоновый расчёт неактивных секторов | по принципу idle-time | не блокирует кадр |
| Ввод, UI, аудио | 2–5 мс | |
| Резерв | 3–5 мс | |

Общая цель: ≤ 33 мс на кадр. Если лимит объектов превышен — снижается liczba активных объектов или упрощается логика.

## 5. microSD (опционально)

- Требуется для: больших карт секторов, музыки, большого количества сохранений.
- **Не считается установленной.** Если microSD absent: сохранения только во flash/PSRAM (ограниченный объём), аудио отсутствует или упрощённое, карты секторов генерируются процедурно.
- Пункт помечается как «требует дополнительного железа».

---

## 6. Риски бюджета

1. 512 КБ SRAM могут не хватить при полной отрисовке и симуляции сектора — потребуется перенос в PSRAM или減шение лимита объектов.
2. PSRAM имеет более высокую задержку, чем SRAM — горячие структуры (изменяемые каждый тик) должны оставаться в SRAM.
3. Flash 16 МБ достаточно для кода и контента, но не для полного набора ресурсов оригинальной Mindustry — нужны свои упрощённые ресурсы.

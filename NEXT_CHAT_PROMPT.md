# Передаточный промт: Campaign Threat Radar (Mindustry v8)

Обновлён 2026-10-18: мод 1.7 сохраняет адаптивный HUD и планировщик защиты.
Новая активная задача: автономно пройти одиночную кампанию Serpulo на Normal без
человека. Пользователь выбрал проектирование под весь путь Serpulo с разработкой
по этапам; первый рабочий этап — один сектор, с паузой/аварийным стопом. Такой
автопилот пока **не реализован**. Ограничения, архитектура и критерии проверки —
в `AUTOPILOT_ROADMAP.md`; `README.md` прямо предупреждает об этом.
Этот файл — источник истины о текущей функциональности проекта.
Читать целиком перед любыми действиями.

## 1. Что это за проект

Клиентский тактический HUD-мод для **Mindustry v8** (билды 154+), репозиторий
`github.com/homa95120-wq/-` (публичный, default branch `main`, имя репозитория —
буквально дефис).

Мод:

1. Расположен в правом верхнем углу, левее миникарты. Отступ считается от
   реальной ширины ванильной миникарты: `MINIMAP_WIDTH = 150`,
   `MINIMAP_GAP = 40` (в UI units). Контент панели — максимум `PANEL_WIDTH = 390`,
   на узких окнах ограничен 38% ширины экрана; карта до `RADAR_SIZE = 220` UI
   units, но не больше 26% высоты экрана. Подписи переносятся по ширине.
2. Показывает **карту всей игровой области** (`campaignradar.RadarMap`,
   отдельный `arc.scene.Element`): пропорции мира сохраняются (letterbox,
   без растяжения), поэтому видны **все** ядра, а не только район слабейшего.
   Синие квадраты — ядра (слабейшее обведено кольцом), белая точка — игрок,
   пустые красные квадраты — спавны волн, красные точки — наземные враги,
   оранжевые — авиация, кольцо — босс. Пунктир соединяет ближайшую угрозу с
   ядром, к которому она идёт. Враги за границей мира прижимаются к краю.
   Если размер мира недоступен, используется bounding box всех известных
   объектов + запас 40 тайлов — далёкие ядра всё равно не пропадают.
   Клик выбирает тайл (letterbox игнорируется), повторный клик снимает выбор.
   По выбранному месту показывается компактная схема, ориентированная на
   ближайший спавн; доступность проверяется по границам, жидкому полу и
   занятым блокам. План не размещает блоки и не меняет мир.
3. **Блок «🎯 Что улучшить» (алгоритм из 1.5, компактный вывод в 1.6).**
   Для каждого ядра проверяются
   подходы от реальных спавнов (`Vars.spawner.getSpawns()`; без спавнов — 8
   направлений при известной угрозе) на кольце 26 тайлов от ядра. Считаются
   только турели, которые реально достают до точки (`range()` × 0.95) и умеют
   бить по нужному слою (`targetGround`/`targetAir`), плюс HP стен в радиусе
   7 тайлов. Каждая метка хранит **нехватку**: `needGround` (DPS по земле),
   `needAir` (DPS по воздуху), `needWall` (HP стен) — именно она печатается
   как «нужно +68/с» / «нужно +1.2k HP».
   Виды и подписи: `ПВО` (нет/мало турелей по воздуху), `ТУРЕЛЬ` (мало урона
   по земле), `СТЕНЫ` (мало HP стен), `ПАТРОНЫ` (турель без патронов, метка на
   самой турели), `РЕМОНТ` (≤35 % HP, метка на точном месте).
   На панели выводятся две самые важные рекомендации; остальные места
   остаются видны на карте с метками ✚. Формат пункта: `ДЕЙСТВИЕ · НАПРАВЛЕНИЕ
   X,Y — чего не хватает`. Номер красный, если метка критична
   (severity ≥ 0.65). Цвет действия совпадает с цветом метки на карте; критичные
   места обведены красным кольцом.
   Без известного контекста угрозы (нет волн/врагов/спавнов) секторные метки
   не ставятся, чтобы не шуметь; метка ремонта возможна всегда.
4. Считает врагов с разбивкой (🚜/🛸/💀), их суммарные оставшиеся HP (HP+щит)
   и DPS, расстояние до ближайшего до ядра.
5. Предсказания:
   - ETA по реальной скорости типа юнита, диапазоном; прогноз на 60 с и время
     жизни ядра.
   - **Прогноз по волнам**: будущие волны строятся из `state.rules.spawns`
     точно как `WaveSpawner.spawnEnemies()` — индекс спавна `state.wave - 1`,
     множитель сложности кампании (боссы округляются вниз), HP ×
     `rules.unitHealth(team)` + `getShield(index)`, DPS × `unitDamage(team)`.
     Ярлык волны = индекс + 2 (номер на счётчике игры во время боя; последняя
     нужная волна = `winWave`). Симуляция до 100 волн: DPS обороны делится по
     слоям с учётом занятых патронами турелей и своих юнитов, пул HP
     «турели+стены» изнашивается и частично чинится, авиация частично бьёт в
     ядро мимо линии, блэкаут режет урон. Краткий вывод: «🏰 Оборона выдержит
     ~N волн · риск на ~M-й: причина» или «🏰 Оборона выдержит до победы».
   - Следующая волна заранее: состав топ-3 типов; босс за ≤10 волн.
6. Диагностика базы: HP ядер, дефицит энергии и блэкаут, турели без патронов,
   повреждённые постройки, статус «✅ Всё спокойно». Срочные предупреждения
   объединяются в одну строку. Патроны/ремонт не дублируются, если для них уже
   есть отдельная метка в рекомендациях.
7. Помечен как `hidden: true` — чисто клиентский мод, не создаёт сущностей, не
   меняет правила, не шлёт сетевые пакеты и не мешает заходить на сервера.

### Формат панели 1.7 (кратко)

```text
РАДАР · Волна 8/30 · следующая через 1:15
Враги: 12 (земля 10, авиация 2)
Сила: HP ~2.4k · урон 132/с · ближайший 50 тайлов
⚠️ К ядру идут 2 · прибытие 8–13 с · ядро может пасть через ~18 с
🎯 Что улучшить: 1) ПВО · СЗ 124,86 — нет защиты от авиации
2) ТУРЕЛЬ · В 210,75 — нужно +68 урона/с · ещё 1 место ✚ на карте
🏰 Оборона выдержит ~6 волн · риск на ~15-й: авиация
Следующая волна 9: 17 врагов · 10×Dagger, 4×Mace
⚠ ⚡ Энергия: не хватает 40/с · батарея 70% (~2:10)
🛡 План защиты · участок 120,84 · фронт СЗ
□ 7 медных стен · ● 4 Duo · ○ 2 Scatter · ✚ 1 Mender (14 мест)
Местность: доступно 14/14 · только рекомендация
```

Правила компактности:
* показывается не более двух рекомендаций; дополнительные места видны на карте;
* предупреждения о ядре/энергии/боеприпасах объединяются в одну строку;
* сессионные счётчики и сводка «сколько всего турелей/юнитов» не выводятся;
* проверка загруженного боя ограничивает текстовую часть десятью строками;
* размер карты и ширина контента адаптируются к коротким и узким экранам;
* клик по карте добавляет компактный план защиты и проверку местности.

Две сборки (**не включать одновременно — будет две панели**):

* **Java (основная):**
  `src/main/java/campaignradar/CampaignThreatRadar.java` (логика + HUD) и
  `src/main/java/campaignradar/RadarMap.java` (карта всей области).
  Корневой `mod.hjson` — имя `campaign-threat-radar`, версия 1.7, `main`,
  `java: true`, `hidden: true`, `minGameVersion: 154`. `build.gradle` — Java 17,
  зависимость `compileOnly Anuken:Mindustry:v160.7`.
* **Скриптовая / ZIP (Rhino JS):**
  `scriptmod/` — порт логики на Rhino-JS API игры (`hidden: true`). Карта
  сделана через `extend(Packages.arc.scene.Element, {...})` (JavaAdapter).
  `scriptmod/mod.hjson` — имя `campaign-threat-radar-zip`, displayName
  `Campaign Threat Radar (ZIP)`, версия 1.7.
  `scriptmod/build.py` собирает `dist/CampaignThreatRadar.zip`.
  Тесты: `node scriptmod/test-logic.js` (52 проверки, включая геометрию плана,
  проверку занятых/водных тайлов и координаты клика) и `node scriptmod/test-hud.js`
  (10 проверок, включая выбор участка и terrain-aware план в HUD).

## 2. Полезные детали API Mindustry v160.7

Проверено по исходникам (тег `v160.7`), а не по памяти:

* `unit.type.speed` — скорость в **world units за тик** (1 тайл = 8 units,
  `Vars.tilesize = 8`); `unit.vel.len()` — та же единица.
* `unit.isFlying()` в v160.7 означает «сейчас в воздухе» (по `elevation`), для
  классификации нужно `unit.type.flying`.
* `UnitType.estimateDps()` — грубая оценка DPS юнита (сумма `Weapon.dps()`).
* `TurretBuild.hasAmmo()`, `TurretBuild.estimateDps()` и `TurretBuild.range()`
  (у `Turret` радиус может меняться патронами; базовое поле — `BaseTurret.range`).
  Цели блока турели: поля `targetGround`/`targetAir` у `Turret`.
* `Vars.world.width()/height()` возвращают размеры мира **в тайлах**;
  `unitWidth()/unitHeight()` — в world units. Координаты тайла центра: `x*8`.
* `Vars.spawner.getSpawns()` — `Seq<Tile>` реальных точек спавна волн;
  мировые координаты — `Tile.worldx()/worldy()`.
* Спавн волны: `SpawnGroup.getSpawned(state.wave - 1)`, щит — `getShield(wave)`,
  босс-группа — `group.effect == StatusEffects.boss`; в скриптах `StatusEffects`
  и `BlockGroup` приходят из `global.js` (`importPackage`).
* Стены в JS надёжно распознаются по `building.block.group === BlockGroup.walls`
  (в Java — то же поле `block.group`).
* `PowerGraph.getPowerBalance()` — за тик (×60 = «/с» на панели);
  `getBatteryStored()/getBatteryCapacity()`.
* `TeamData.cores` — `Seq<CoreBuild>`, `TeamData.buildings` — `Seq<Building>`;
  предметы главного ядра — `CoreBuild.items.total()`.
* `Vars.state.stats` — `GameStats`: `enemyUnitsDestroyed`, `buildingsBuilt`,
  `buildingsDestroyed`, `unitsCreated` (панель их не показывает).
* `Vars.player.unit()` — контролируемый юнит (может быть `null`). Поле `Player.unit`
  **protected**, обращаться к нему из мода нельзя — только через метод `unit()`
  (иначе сборка в CI падает с «unit has protected access in Player»).
* `arc.struct.Seq.toString(String separator)` — список имён через запятую.
* Ванильная миникарта: `mindustry.ui.Minimap` шириной `Scl.scl(140)` + отступ 5.

## 3. Команды для сборки и тестов

```bash
node scriptmod/test-logic.js
node scriptmod/test-hud.js
python3 scriptmod/build.py
git status
```

Локально в песочнице нет JDK, поэтому jar собирается только в CI
(`.github/workflows/build.yml`, триггер — push в любую ветку). Перед коммитом
обязательно прогонять `node scriptmod/test-logic.js` и `node scriptmod/test-hud.js`;
синтаксис Java можно быстро проверить npm-пакетом `java-parser`, но типы и API
окончательно проверяет только CI-сборка `./gradlew jar`. План участка —
эвристическая стартовая схема: она не учитывает технологический уровень,
ресурсы, линии огня и конкретные правила размещения построек.

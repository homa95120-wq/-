## 1. Что это за проект

Клиентский тактический HUD-мод для **Mindustry v8** (билды 154+), репозиторий
`github.com/homa95120-wq/-` (публичный, default branch `main`, имя репозитория —
буквально дефис).

Мод:

1. Расположен в правом верхнем углу, левее миникарты. Отступ считается от
   реальной ширины ванильной миникарты: `Scl.scl(MINIMAP_WIDTH + MINIMAP_GAP)`,
   где `MINIMAP_WIDTH = 150`, `MINIMAP_GAP = 70` (в UI units).
2. Показывает **карту всей игровой области** (`campaignradar.RadarMap`,
   отдельный `arc.scene.Element`): пропорции мира сохраняются (letterbox,
   без растяжения), поэтому видны **все** ядра, а не только район слабейшего.
   Синие квадраты — ядра (слабейшее обведено кольцом), белая точка — игрок,
   пустые красные квадраты — спавны волн, красные точки — наземные враги,
   оранжевые — авиация, кольцо — босс. Пунктир соединяет ближайшую угрозу с
   ядром, к которому она идёт. Враги за границей мира прижимаются к краю.
   Если размер мира недоступен, используется bounding box всех известных
   объектов + запас 40 тайлов — далёкие ядра всё равно не пропадают.
3. **Метки усиления обороны ✚** (до 3): для каждого ядра проверяются подходы
   от реальных спавнов (`Vars.spawner.getSpawns()`; без спавнов — 8 направлений
   при известной угрозе) на кольце 26 тайлов от ядра. Считаются только турели,
   которые реально достают до точки (`range()` × 0.95) и умеют бить по нужному
   слою (`targetGround`/`targetAir`), плюс HP стен в радиусе 7 тайлов.
   Виды: мало урона по земле, слабое/нет ПВО, нужны стены, турель без патронов
   (метка на самой турели), ремонт самой повреждённой постройки передовой
   (≤35% HP, метка на точном месте). В тексте: направление от ядра (СЗ/В/…)
   и координаты тайла. Без известного контекста угрозы (нет волн/врагов/спавнов)
   секторные метки не ставятся, чтобы не шуметь; метка ремонта возможна всегда.
4. Считает врагов с разбивкой (🚜/🛸/💀), их суммарные оставшиеся HP (HP+щит)
   и DPS, расстояние до ближайшего до ядра.
5. Предсказания:
   - ETA по реальной скорости типа юнита, диапазоном; прогноз на 60 с и время
     жизни ядра — как в 1.3.
   - **Прогноз по волнам**: будущие волны строятся из `state.rules.spawns`
     точно как `WaveSpawner.spawnEnemies()` — индекс спавна `state.wave - 1`,
     множитель сложности кампании (боссы округляются вниз), HP ×
     `rules.unitHealth(team)` + `getShield(index)`, DPS × `unitDamage(team)`.
     Ярлык волны = индекс + 2 (это номер на счётчике игры во время боя;
     последняя нужная волна = `winWave`). Симуляция до 100 волн: DPS обороны
     делится по слоям с учётом занятых патронами турелей и своих юнитов, пул HP
     «турели+стены» изнашивается и частично чинится, авиация частично бьёт в
     ядро мимо линии, блэкаут режет урон. Результат: «ещё ~N волн · падёт
     на ~M-й — причина» или «дотянет до победы».
   - Следующая волна заранее: состав топ-3 типов, ΣHP/DPS; босс за ≤10 волн.
6. Статистика базы и сессии: построек/турелей, DPS с разбивкой 🚜/🛸/🤖,
   свои юниты, баланс энергии и на сколько хватит АКБ при дефиците, предметов
   в главном ядре, счётчики `GameStats` (убито/построено/потеряно/создано).
7. Диагностика базы: HP ядер, дефицит энергии и блэкаут, турели без патронов,
   повреждённые постройки, статус «Все системы стабильны» (не показывается,
   если есть метки усиления).
8. Помечен как `hidden: true` — чисто клиентский мод, не создаёт сущностей, не
   меняет правила, не шлёт сетевые пакеты и не мешает заходить на сервера.

Две сборки (**не включать одновременно — будет две панели**):

* **Java (основная):**
  `src/main/java/campaignradar/CampaignThreatRadar.java` (логика + HUD) и
  `src/main/java/campaignradar/RadarMap.java` (карта всей области).
  Корневой `mod.hjson` — имя `campaign-threat-radar`, версия 1.4, `main`,
  `java: true`, `hidden: true`, `minGameVersion: 154`. `build.gradle` — Java 17,
  зависимость `compileOnly Anuken:Mindustry:v160.7`.
* **Скриптовая / ZIP (Rhino JS):**
  `scriptmod/` — порт логики на Rhino-JS API игры (`hidden: true`). Карта
  сделана через `extend(Packages.arc.scene.Element, {...})` (JavaAdapter).
  `scriptmod/mod.hjson` — имя `campaign-threat-radar-zip`, displayName
  `Campaign Threat Radar (ZIP)`, версия 1.4.
  `scriptmod/build.py` собирает `dist/CampaignThreatRadar.zip`.
  Тесты: `node scriptmod/test-logic.js` (44 проверки, включая проекцию всей
  карты и каждый вид метки) и `node scriptmod/test-hud.js` (8 проверок,
  включая далёкое второе ядро в кадре карты).

## 2. Полезные детали API Mindustry v160.7

Проверено по исходникам (тег `v160.7`), а не по памяти:

* `unit.type.speed` — скорость в **world units за тик** (1 тайл = 8 units,
  `Vars.tilesize = 8`); `unit.vel.len()` — та же единица.
* `unit.isFlying()` в v160.7 означает «сейчас в воздухе» (по `elevation`), для
  классификации нужно `unit.type.flying`.
* `UnitType.estimateDps()` — грубая оценка DPS юнита (сумма `Weapon.dps()`).
* `TurretBuild.hasAmmo()`, `TurretBuild.estimateDps()` и `TurretBuild.range()`
  (у `Turret` радиус может меняться патронами; базовое поле — `BaseTurret.range`).
  Цели блока турели: поля `targetGround`/`targetAir` у `Turret`.
* `Vars.world.width()/height()` возвращают размеры мира **в тайлах**;
  `unitWidth()/unitHeight()` — в world units. Координаты тайла центра: `x*8`.
* `Vars.spawner.getSpawns()` — `Seq<Tile>` реальных точек спавна волн;
  мировые координаты — `Tile.worldx()/worldy()`.
* Спавн волны: `SpawnGroup.getSpawned(state.wave - 1)`, щит — `getShield(wave)`,
  босс-группа — `group.effect == StatusEffects.boss`; в скриптах `StatusEffects`
  и `BlockGroup` приходят из `global.js` (`importPackage`).
* Стены в JS надёжно распознаются по `building.block.group === BlockGroup.walls`
  (в Java — то же поле `block.group`).
* `PowerGraph.getPowerBalance()` — за тик (×60 = «/с» на панели);
  `getBatteryStored()/getBatteryCapacity()`.
* `TeamData.cores` — `Seq<CoreBuild>`, `TeamData.buildings` — `Seq<Building>`;
  предметы главного ядра — `CoreBuild.items.total()`.
* `Vars.state.stats` — `GameStats`: `enemyUnitsDestroyed`, `buildingsBuilt`,
  `buildingsDestroyed`, `unitsCreated`.
* `Vars.player.unit()` — контролируемый юнит (может быть `null`). Поле `Player.unit`
  **protected**, обращаться к нему из мода нельзя — только через метод `unit()`
  (иначе сборка в CI падает с «unit has protected access in Player»).
* Ванильная миникарта: `mindustry.ui.Minimap` шириной `Scl.scl(140)` + отступ 5.

## 3. Команды для сборки и тестов

```bash
node scriptmod/test-logic.js
node scriptmod/test-hud.js
python3 scriptmod/build.py
git status
```

Локально в песочнице нет JDK, поэтому jar собирается только в CI
(`.github/workflows/build.yml`, триггер — push в любую ветку). Перед коммитом
обязательно прогонять `node scriptmod/test-logic.js` и `node scriptmod/test-hud.js`;
синтаксис Java можно быстро проверить npm-пакетом `java-parser`, но типы и API
окончательно проверяет только CI-сборка `./gradlew jar`.

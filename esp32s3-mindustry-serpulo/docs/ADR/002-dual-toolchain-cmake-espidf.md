# ADR-002: Двухтулчейновая сборка (Host CMake ≥ 3.20 + ESP-IDF 5.3.x)

- **Статус:** Принято (M0 → M8)
- **Дата:** 2026-10-25
- **Контекст:** Одни и те же исходники `simcore/` должны без условных правок собираться как статическая библиотека на ПК (Windows/Linux/macOS) и как компонент прошивки ESP-IDF 5.3.x (`target: esp32s3`).

## Решение

1. В `simcore/CMakeLists.txt` используется проверка `if(ESP_PLATFORM)`:
   - При сборке под **ESP-IDF** вызывается `idf_component_register(SRCS ... INCLUDE_DIRS "include")` с флагами `-std=gnu++17 -fno-exceptions -fno-rtti`.
   - При сборке на **ПК** создаётся `add_library(simcore STATIC ...)` с C++17 без расширений компилятора, `-fno-exceptions -fno-rtti` (или `/EHs-c- /GR-` для MSVC).
2. Разделение памяти между SRAM и PSRAM инкапсулировано на уровне владения памятью:
   - `SimHotState` (~58 КБ: здания, юниты, снаряды, энергосеть, инвентарь ядра, очередь команд) размещается во внутренней **SRAM** ESP32-S3 (`MALLOC_CAP_INTERNAL`).
   - `SimMapStorage` (~112 КБ: тайлы 128×128, руды, стены, индекс зданий, BFS flow-field) размещается в **Octal PSRAM** (`MALLOC_CAP_SPIRAM`).
   - На ПК обе структуры размещаются в обычной оперативной памяти.
3. Клиент `client-pc` линкует и `simcore` (для автономной одиночной игры 60 TPS на ПК — **Путь A**), и сетевой/последовательный клиент протокола `0x4D53` (для подключения к плате ESP32-S3 по Wi-Fi TCP или USB-CDC — **Путь B**).

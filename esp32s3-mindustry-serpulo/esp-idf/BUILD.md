# Сборка прототипа ESP-IDF

Требуется: ESP-IDF v5.x + инструментарий xtensa/esp32s3 (не установлены в песочнице).

```bash
cd esp32s3-mindustry-serpulo/esp-idf

# Выбрать цель
idf.py set-target esp32s3

# Собрать
idf.py build

# Прошить (после подключения платы)
idf.py -p /dev/ttyUSB0 flash

# Монитор порта
idf.py -p /dev/ttyUSB0 monitor
```

## Что делает прототип (этап 4)

- Инициализирует активный сектор 128×128 тайлов
- Прокладывает водяные трубы от источника к резервуару
- Ставит генератор, батарею и потребитель (турель) — считает баланс энергии за тик
- Прокладывает конвейеры и подаёт на них предмет (медь)
- Спавнит вражеского юнита и снаряд — моделирует полёт и попадание
- Пробует построить путь A* от (25,25) к (20,2)
- Каждую секунду выводит статистику в ESP_LOG (tick, волна, баланс энергии, дефицит, юниты, снаряды)

## Известные ограничения прототипа

1. **Не скомпилировано в песочнице** — нет ESP-IDF toolchain и платы ESP32-S3. Требуется проверка на реальном железе (этап 5).
2. `fluid_tick` использует статический массив `delta` 128×128 float (~64 КБ в BSS) — накладно, но помещается в 512 КБ SRAM. При необходимости перенести в PSRAM.
3. `pf_nodes` в pathfinding (~48 КБ в BSS) — аналогично.
4. Нет сетевого протокола клиент-сервер (Wi-Fi TCP) — только локальный демо-цикл. Протокол описан в `docs/PROTOCOL.md`.
5. Нет дисплея/рендеринга — headless-сервер, как и требуется для клиент-серверной архитектуры.
